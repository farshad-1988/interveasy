## 1. Basic SELECT / WHERE / ORDER BY / LIMIT

### Feedback table

```sql
-- Get the 10 most recent feedback entries
SELECT id, "authorId", "subjectId", "interviewId", category, score, comment, "createdAt"
FROM "Feedback"
ORDER BY "createdAt" DESC
LIMIT 10;
-- Use: Latest feedback dashboard, pagination page 1.

-- Get all feedback for a specific subject user, filtered by category
SELECT id, category, score, comment, "createdAt"
FROM "Feedback"
WHERE "subjectId" = 'USER-UUID-HERE'
  AND category = 'TECHNICAL'
ORDER BY "createdAt" DESC;
-- Use: Show a candidate's technical interview history.

-- Feedback with a score above 3
SELECT id, "subjectId", category, score
FROM "Feedback"
WHERE score > 3
ORDER BY score DESC, "createdAt" DESC
LIMIT 50;
-- Use: Finding high-scoring candidates for fast-track hiring.
```

### Leads table

```sql
-- All new leads, newest first
SELECT id, "fullName", email, company, status, "createdAt"
FROM "Lead"
WHERE status = 'NEW'
ORDER BY "createdAt" DESC;
-- Use: Admin dashboard — unprocessed demo requests.

-- Leads from a specific source, limited to 20
SELECT id, "fullName", email, source, status
FROM "Lead"
WHERE source = 'REFERRAL'
ORDER BY "createdAt" DESC
LIMIT 20;
-- Use: Measuring referral program effectiveness.

-- Search leads by company name (case-insensitive)
SELECT id, "fullName", email, company, status
FROM "Lead"
WHERE company ILIKE '%acme%'
ORDER BY "createdAt" DESC;
-- Use: CRM-style company search.
```

### Interviews table

```sql
-- All confirmed interviews scheduled in the next 7 days
SELECT id, title, "userId", "interviewerId", "startAt", "endAt", status
FROM "Interview"
WHERE status = 'CONFIRMED'
  AND "startAt" BETWEEN NOW() AND NOW() + INTERVAL '7 days'
ORDER BY "startAt" ASC;
-- Use: Upcoming interviews widget for interviewers.

-- Get a single interview with all columns
SELECT *
FROM "Interview"
WHERE id = 'INTERVIEW-UUID-HERE';
-- Use: Interview detail page.

-- All interviews for a candidate
SELECT id, title, status, "startAt", "endAt"
FROM "Interview"
WHERE "userId" = 'USER-UUID-HERE'
ORDER BY "startAt" DESC
LIMIT 10;
-- Use: Candidate's interview history.
```

## 2. INNER JOIN Examples

### Feedback + User + Interview

```sql
-- Get feedback with author name, subject name, and interview title
SELECT
  f.id,
  f.category,
  f.score,
  f.comment,
  f."createdAt",
  author.name   AS "authorName",
  author.email  AS "authorEmail",
  subject.name  AS "subjectName",
  i.title       AS "interviewTitle"
FROM "Feedback" f
INNER JOIN "User" author  ON author.id  = f."authorId"
INNER JOIN "User" subject ON subject.id = f."subjectId"
INNER JOIN "Interview" i  ON i.id       = f."interviewId"
ORDER BY f."createdAt" DESC;
-- Use: Full feedback report — combines all three entities in one query.
-- Why INNER JOIN: Every feedback row must have a valid author, subject, and interview (enforced by FK + onDelete:Cascade).

-- Get feedback score alongside interview status
SELECT
  f.id,
  f.category,
  f.score,
  i.status AS "interviewStatus",
  i."startAt"
FROM "Feedback" f
INNER JOIN "Interview" i ON i.id = f."interviewId"
WHERE i.status = 'COMPLETED'
ORDER BY i."startAt" DESC;
-- Use: Analytics — only count feedback from completed interviews.
```

## 3. LEFT JOIN Examples

### Users with their feedback (including users who have no feedback)

```sql
-- All users and how many times they've received feedback
SELECT
  u.id,
  u.name,
  u.email,
  COUNT(f.id) AS "feedbackCount"
FROM "User" u
LEFT JOIN "Feedback" f ON f."subjectId" = u.id
GROUP BY u.id, u.name, u.email
ORDER BY "feedbackCount" DESC;
-- Use: Identifying candidates who haven't been evaluated yet (feedbackCount = 0).
-- Why LEFT JOIN: Preserves users who have received no feedback.

-- Users and their most recent feedback score
SELECT
  u.id,
  u.name,
  f.score        AS "latestScore",
  f.category     AS "latestCategory",
  f."createdAt"  AS "feedbackAt"
FROM "User" u
LEFT JOIN LATERAL (
  SELECT score, category, "createdAt"
  FROM "Feedback"
  WHERE "subjectId" = u.id
  ORDER BY "createdAt" DESC
  LIMIT 1
) f ON true
ORDER BY u.name;
-- Use: User list with quick-glance latest evaluation.
-- LATERAL JOIN: Correlated subquery evaluated per row — efficient with the index on (subjectId, createdAt).

-- Leads with their assigned admin (NULL if unassigned)
SELECT
  l.id,
  l."fullName",
  l.email,
  l.status,
  u.name  AS "assignedToName",
  u.email AS "assignedToEmail"
FROM "Lead" l
LEFT JOIN "User" u ON u.id = l."assignedToId"
ORDER BY l."createdAt" DESC;
-- Use: Lead management view — shows unassigned leads as NULL.
```

## 4. GROUP BY + HAVING

### Feedback by category with minimum score filter

```sql
-- Average score per category, only show categories with avg > 2.5
SELECT
  category,
  COUNT(*)          AS total,
  ROUND(AVG(score), 2) AS avg_score,
  MIN(score)        AS min_score,
  MAX(score)        AS max_score
FROM "Feedback"
GROUP BY category
HAVING AVG(score) > 2.5
ORDER BY avg_score DESC;
-- Use: Analytics — which interview dimensions are performing well.
-- HAVING filters AFTER grouping (WHERE filters before).

-- Categories where the minimum score is below 2 (problem areas)
SELECT
  category,
  COUNT(*)  AS total,
  MIN(score) AS min_score
FROM "Feedback"
GROUP BY category
HAVING MIN(score) < 2
ORDER BY min_score ASC;
-- Use: Flag areas needing coaching attention.

-- Lead counts by status
SELECT
  status,
  COUNT(*) AS lead_count
FROM "Lead"
GROUP BY status
ORDER BY lead_count DESC;
-- Use: Pipeline health dashboard.

-- Lead counts by source, only sources with more than 5 leads
SELECT
  source,
  COUNT(*) AS lead_count
FROM "Lead"
GROUP BY source
HAVING COUNT(*) > 5
ORDER BY lead_count DESC;
-- Use: Marketing channel effectiveness — ignore low-volume sources.
```

## 5. AVG / COUNT / MIN / MAX

```sql
-- Overall feedback statistics per subject user
SELECT
  "subjectId",
  COUNT(*)               AS total_feedback,
  ROUND(AVG(score), 2)  AS avg_score,
  MIN(score)             AS min_score,
  MAX(score)             AS max_score
FROM "Feedback"
GROUP BY "subjectId"
ORDER BY avg_score DESC;
-- Use: Leaderboard / candidate performance ranking.

-- Average score per category per subject (performance breakdown)
SELECT
  "subjectId",
  category,
  COUNT(*)               AS count,
  ROUND(AVG(score), 2)  AS avg_score
FROM "Feedback"
GROUP BY "subjectId", category
ORDER BY "subjectId", category;
-- Use: Per-candidate radar chart data.

-- Count of leads per month
SELECT
  DATE_TRUNC('month', "createdAt") AS month,
  COUNT(*)                          AS new_leads
FROM "Lead"
GROUP BY month
ORDER BY month DESC;
-- Use: Monthly lead volume trend.

-- Interview count by status
SELECT
  status,
  COUNT(*) AS interview_count
FROM "Interview"
GROUP BY status;
-- Use: Operations overview — how many in each stage.
```

## 6. Date Range Filter Examples

```sql
-- Feedback submitted in the last 30 days
SELECT id, "subjectId", category, score, "createdAt"
FROM "Feedback"
WHERE "createdAt" >= NOW() - INTERVAL '30 days'
ORDER BY "createdAt" DESC;
-- Use: Recent feedback feed.

-- Feedback submitted in a specific calendar month
SELECT id, category, score, "createdAt"
FROM "Feedback"
WHERE "createdAt" >= '2025-01-01'
  AND "createdAt" <  '2025-02-01'
ORDER BY "createdAt" ASC;
-- Use: Monthly reporting — always use < next-month-start, not <= last-day, to be timezone-safe.

-- Interviews scheduled within a date range
SELECT id, title, "startAt", status
FROM "Interview"
WHERE "startAt" >= '2025-03-01'
  AND "startAt" <  '2025-04-01'
ORDER BY "startAt" ASC;
-- Use: Monthly interview calendar export.

-- Leads created this week
SELECT id, "fullName", email, status, "createdAt"
FROM "Lead"
WHERE "createdAt" >= DATE_TRUNC('week', NOW())
ORDER BY "createdAt" DESC;
-- Use: Weekly sales team standup.

-- Trend: feedback count per week over last 12 weeks
SELECT
  DATE_TRUNC('week', "createdAt") AS week_start,
  COUNT(*)                         AS feedback_count
FROM "Feedback"
WHERE "createdAt" >= NOW() - INTERVAL '12 weeks'
GROUP BY week_start
ORDER BY week_start ASC;
-- Use: Trend line chart for analytics dashboard.
```

## 7. EXPLAIN ANALYZE — Before Adding Indexes

Before adding any index, run `EXPLAIN ANALYZE` to verify query performance and confirm the index is actually used.

### Template

```sql
EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
SELECT *
FROM "Feedback"
WHERE "subjectId" = 'USER-UUID-HERE'
ORDER BY "createdAt" DESC
LIMIT 10;
```

### Example output template (what to look for)

```
Limit  (cost=0.43..8.45 rows=10 width=256) (actual time=0.123..0.145 rows=10 loops=1)
  ->  Index Scan using "Feedback_subjectId_createdAt_idx" on "Feedback"
        (cost=0.43..84.50 rows=100 width=256)
        (actual time=0.120..0.138 rows=10 loops=1)
        Index Cond: ("subjectId" = 'USER-UUID-HERE')
Planning Time: 0.312 ms
Execution Time: 0.178 ms
```

**What to look for:**
| Node type | Meaning |
|---|---|
| `Index Scan` | ✅ Index is being used |
| `Seq Scan` | ⚠️ Full table scan — add or fix index |
| `Bitmap Heap Scan` | ✅/⚠️ Partial index use — OK for large result sets |
| High `actual time` | ⚠️ Query is slow despite index — check selectivity |
| `Buffers: shared hit` | ✅ Data in cache |
| `Buffers: shared read` | ⚠️ Disk I/O — cache miss |

**Procedure:**
1. Run `EXPLAIN ANALYZE` on the slow query
2. Look for `Seq Scan` on large tables
3. Add the index on the filtered/sorted column(s)
4. Re-run `EXPLAIN ANALYZE` and confirm `Index Scan` is used
5. Measure `Execution Time` before and after

## 8. Schema Index Documentation

### Feedback indexes

| Index | Columns | Justification |
|---|---|---|
| `Feedback_subjectId_idx` | `subjectId` | Most common filter — "show feedback for user X" |
| `Feedback_interviewId_idx` | `interviewId` | Join from Interview → Feedback |
| `Feedback_authorId_idx` | `authorId` | "Show feedback I wrote" (author's history) |
| `Feedback_category_idx` | `category` | Filter by category in analytics queries |
| `Feedback_createdAt_idx` | `createdAt` | Date range filters, trend queries |
| `Feedback_subjectId_category_idx` | `(subjectId, category)` | Composite: per-user per-category breakdown (performance radar) |
| `Feedback_subjectId_createdAt_idx` | `(subjectId, createdAt)` | Composite: candidate's feedback timeline, paginated |
| `@@unique([authorId, interviewId, category])` | `(authorId, interviewId, category)` | Business rule: one feedback per author/interview/category combination. Also serves as an index. |

### Lead indexes

| Index | Columns | Justification |
|---|---|---|
| `Lead_email_idx` | `email` | Duplicate-active-email check on lead creation |
| `Lead_status_idx` | `status` | Filter by pipeline stage (admin dashboard) |
| `Lead_createdAt_idx` | `createdAt` | Date range queries, newest-first list |
| `Lead_source_idx` | `source` | Marketing analytics by channel |
| `Lead_assignedToId_idx` | `assignedToId` | "Show leads assigned to me" |
| `Lead_status_createdAt_idx` | `(status, createdAt)` | Composite: filtered pipeline sorted by recency |

### Interview indexes (existing)

| Index | Columns | Justification |
|---|---|---|
| `Interview_userId_idx` | `userId` | Candidate's interview list |
| `Interview_interviewerId_idx` | `interviewerId` | Interviewer's schedule |
| `Interview_status_idx` | `status` | Filter by lifecycle stage |
| `Interview_startAt_idx` | `startAt` | Date range scheduling queries |
| `Interview_endAt_idx` | `endAt` | Overlap detection for double-booking |
| `Interview_userId_startAt_idx` | `(userId, startAt)` | Candidate's upcoming interviews (most common view) |
| `Interview_interviewerId_startAt_idx` | `(interviewerId, startAt)` | Interviewer's upcoming schedule |
| `Interview_assessmentId_idx` | `assessmentId` | Join from Assessment → Interview |

---

> **Performance tip**: Composite indexes are only used when the query filters on the **leading column** first. `(subjectId, category)` helps `WHERE subjectId = X AND category = Y` but not `WHERE category = Y` alone. For the latter, the single-column `Feedback_category_idx` is used.
